# ЛР1 — Планирование процессов с помощью таймеров (Python)

Аналог Java-классов `Timer` / `TimerTask` на Python и приложение с несколькими таймерами.

| Файл | Что внутри |
|---|---|
| `timer_lib.py` | Классы `Timer` и `TimerTask`: `schedule()`, `schedule_at_fixed_rate()` (синоним `scheduleAtFixedRate`), `cancel()` |
| `console_demo.py` | Консольная версия примера `TimerApp` из методички |
| `app.py` | Окно (tkinter) с 5 таймерами в разных режимах |

## Запуск

```bash
python console_demo.py   # консоль
python app.py            # графический интерфейс
```
Нужен только Python 3.9+ (tkinter входит в стандартную поставку Windows/macOS; в Linux: `sudo apt install python3-tk`).

## Режимы из задания

1. **Через определённый промежуток времени** — `timer.schedule(task, 5)`: один запуск через 5 с.
2. **В течение определённого времени** — таймер №1 `scheduleAtFixedRate(task, 1, 1)` тикает каждую секунду, таймер №2 `schedule(stopper, N)` через N секунд вызывает `cancel()` у первого.
3. **С указанным периодом** — `schedule(task, 0, period)` (фикс. задержка) или `scheduleAtFixedRate(task, 0, period)` (фикс. частота). Галочка «3-й запуск тормозит» показывает разницу: при фиксированной частоте пропущенные запуски выполняются подряд («догоняют»), при фиксированной задержке всё расписание сдвигается.
4. Дополнительно: **будильник** — `schedule(task, datetime)`, срабатывание в точное время.

## Как устроен Timer

- У каждого `Timer` свой поток (`threading.Thread`) и очередь задач, отсортированная по времени запуска (`heapq`).
- Поток спит (`Condition.wait`) до времени ближайшей задачи, затем вызывает `task.run()`.
- Периодическая задача перед запуском снова кладётся в очередь:
  фикс. частота → `плановое_время + period`, фикс. задержка → `фактическое_время + period`.
- `cancel()` очищает очередь и завершает поток; повторно использовать таймер нельзя (как в Java).
- В GUI задачи не меняют окно напрямую (tkinter не потокобезопасен), а передают функцию через `queue.Queue` в главный поток.

## Контрольные вопросы

1. **Что такое Git?** Распределённая система управления версиями: хранит историю изменений файлов, у каждого участника полная копия репозитория.
2. **Основные компоненты:** рабочая директория, индекс (staging area), локальный репозиторий (`.git`: коммиты, ветки), удалённый репозиторий (remote, напр. GitHub).
3. **Основные функции:** фиксация изменений (commit), ветвление и слияние (branch/merge), клонирование (clone), синхронизация (push/pull/fetch), просмотр истории и откат.
4. **Таймер** — механизм, который уведомляет программу (запускает действие) по истечении заданного интервала времени, однократно или периодически.
5. **`schedule()`** — метод класса `java.util.Timer`; планирует выполнение `TimerTask` однократно (через задержку или в момент времени) или повторно с фиксированной задержкой.
6. **Шаги:** создать подкласс `TimerTask` и переопределить `run()` → создать объект `Timer` → создать объект-действие → запланировать его методом `schedule()` / `scheduleAtFixedRate()`.
7. **`schedule()` vs `scheduleAtFixedRate()`:** первый — фиксированная задержка (если запуск опоздал, все следующие сдвигаются); второй — фиксированная частота (опоздавшие запуски выполняются быстрее, чтобы общее число запусков за период не менялось).
8. **Когда прекращается:** после выполнения однократной задачи / когда задачи кончились и на таймер нет ссылок, при вызове `cancel()`, при завершении программы.
9. **Принудительная остановка:** `Timer.cancel()` (весь таймер), `TimerTask.cancel()` (одна задача), `System.exit()` (вся программа; в Python — `sys.exit()`).
